# 맛집로그(MatLog) 기획서

> 서비스 이름은 임시안입니다. 다른 후보: "한입리뷰", "맛집노트"

## 1. 서비스 개요

**한 줄 소개**: 사용자가 식당 정보를 등록하고, 방문한 식당에 별점과 리뷰를 남기며, 식당별 평균 별점을 확인하는 콘솔 프로그램이다.

**대상 사용자**
- 회원: 맛집을 등록하고, 방문 후 별점과 리뷰를 남기는 사람

**해결하려는 문제**
- 맛집 정보와 후기가 여러 곳에 흩어져 있어, 한 곳에서 확인하고 비교하기 어렵다.
- 후기 글만으로는 가게 수준을 한눈에 알기 어렵다. 별점을 평균으로 집계해 보여주고, 가게당 1인 1리뷰로 한 사람이 평점을 부풀리는 것을 막는다.

**기술 제약**
- Java 콘솔 프로그램 (웹 화면 없음, 메뉴 번호 입력 방식)
- MySQL + JDBC, MVC 패턴
- 결제, 파일 업로드, 이메일 인증은 제외

| O-05 | 비밀번호 해시 저장 | 저장·비교 시 해시 적용 | 선택 | 팀원A |
| O-06 | 본인 가게 리뷰 금지 | 본인이 등록한 가게에는 리뷰 작성 불가 | 선택 | 팀원C |
| O-07 | 맛집 중복 등록 방지 | 같은 이름+주소면 등록 거부 | 선택 | 팀원B |
| O-08 | 카테고리 고정 목록 | 한식·중식·일식·양식·기타 중 번호 선택 | 선택 | 팀원B |

선택 기능은 필수가 모두 끝난 뒤, 여유가 있을 때만 구현한다. 모두 빼도 필수 기능은 정상 동작한다. 팀원별 담당 테이블의 등록·조회·수정·삭제(CRUD)는 필수 기능에 모두 들어 있다. 회원은 F-01(등록), F-02(조회), F-03(수정·삭제), 맛집은 F-04(등록), F-05(조회), F-06(수정·삭제), 리뷰는 F-07(등록), F-08(조회), F-09(수정·삭제)이다.

## 3. 운영 규칙

1. 가입과 로그인을 제외한 모든 기능은 로그인 후에만 이용할 수 있다. 비로그인 상태에서는 가입·로그인·종료만 보인다.
2. 가게를 삭제하면 그 가게에 달린 리뷰도 함께 삭제된다. 삭제 확인 문구에 이 사실을 안내한다.
3. 작성한 리뷰나 등록한 가게가 있는 회원은 탈퇴할 수 없다. 먼저 해당 리뷰와 가게를 삭제해야 한다.
4. 가게당 한 회원은 리뷰를 1개만 쓸 수 있다.
5. 리뷰가 없는 가게의 평균 별점은 "평점 없음"으로 표시한다.

## 4. 기능 명세 (필수 기능)

### F-01 회원 가입
- **입력**: 아이디, 비밀번호, 닉네임
- **처리**: 빈 값 검증 → 아이디·닉네임 중복 확인 → 저장. 중복 확인 후 저장 중에 UNIQUE 위반(MySQL 오류 코드 1062)이 나도 같은 중복 메시지로 처리한다.
- **출력**: "가입 완료" / "이미 존재하는 아이디" / "이미 사용 중인 닉네임" / "입력값을 확인해 주세요"

### F-02 로그인 / 로그아웃
- **입력**: 아이디, 비밀번호
- **처리**: 아이디·비밀번호가 일치하는 회원 조회 → 있으면 LoginSession에 회원 저장 (로그아웃은 세션 비우기). 틀린 아이디와 틀린 비밀번호는 같은 메시지로 처리한다.
- **출력**: "OOO님 환영합니다" / "아이디 또는 비밀번호가 올바르지 않습니다" / "로그아웃되었습니다"

### F-03 내 정보 수정 / 탈퇴
- **입력**: 메뉴 선택(닉네임 수정 / 회원 탈퇴)
    - 닉네임 수정: 새 닉네임
    - 회원 탈퇴: 현재 비밀번호, 확인(Y/N)
- **처리**
    - 닉네임 수정: 빈 값 검증 → 현재 닉네임과 같은지 확인 → 다른 회원과 중복 확인 → 저장 → LoginSession의 닉네임 갱신
    - 회원 탈퇴: 비밀번호 일치 확인 → "정말 탈퇴할까요? (Y/N)" (Y/y만 진행) → 회원 삭제 시도. 작성한 리뷰나 등록한 가게가 있으면 FK 제약 위반 예외가 발생한다. `SQLException`의 `getErrorCode()`가 1451(삭제하려는 행을 다른 테이블이 참조 중)인 경우에만 탈퇴 불가로 처리하고, 그 밖의 `SQLException`(DB 연결 오류 등)은 "DB 오류가 발생했습니다" 메시지로 따로 처리한다. 성공하면 세션을 비우고 로그인 전 메뉴로 이동한다.
- **출력**: "수정 완료" / "현재 닉네임과 같습니다" / "이미 사용 중인 닉네임" / "탈퇴가 완료되었습니다" / "취소되었습니다" / "비밀번호가 올바르지 않습니다" / "작성한 리뷰나 등록한 맛집이 있어 탈퇴할 수 없습니다" / "DB 오류가 발생했습니다"

### F-04 맛집 등록
- **입력**: 가게 이름, 주소, 지역, 카테고리
- **처리**: 빈 값 검증 → 저장 (등록자 = 현재 로그인 회원)
- **출력**: "맛집 등록 완료" / "입력값을 확인해 주세요"

### F-05 맛집 목록 조회
- **입력**: 없음 (메뉴 선택만)
- **처리**: 전체 맛집을 등록순으로 조회
- **출력**: 가게 번호, 이름, 카테고리, 지역 목록 / "등록된 맛집이 없습니다"

### F-06 내 맛집 수정 / 삭제
- **입력**: 내 맛집 목록에서 가게 번호 선택, 수정 또는 삭제 선택, 수정할 새 값 / 삭제 확인(Y/N)
- **처리**: 내가 등록한 맛집 목록 조회(0개면 종료) → 입력한 번호가 그 목록에 있는지 확인 → 수정은 이름·주소·지역·카테고리 새 값을 받아 저장(빈 값 거부), 삭제는 "리뷰도 함께 삭제됩니다. 정말 삭제할까요? (Y/N)" 확인 후 삭제 (Y/y만 진행)
- **출력**: "수정 완료" / "삭제 완료" / "취소되었습니다" / "등록한 맛집이 없습니다" / "본인이 등록한 가게만 선택할 수 있습니다"

### F-07 리뷰 작성
- **입력**: 가게 번호, 별점(1~5), 리뷰 내용
- **처리**: 별점 검증(정수, 1~5) → 내용 빈 값 검증 → 이미 쓴 리뷰가 있는지 확인 → 저장. 저장 중 `SQLException`의 `getErrorCode()`가 1452(참조할 가게가 없음)이면 "존재하지 않는 가게입니다"로, 1062(UNIQUE 위반, 동시 작성 등)이면 "이미 리뷰를 작성한 가게입니다"로 처리하고, 그 밖의 오류는 "DB 오류가 발생했습니다"로 처리한다.
- **출력**: "리뷰 등록 완료" / "이미 리뷰를 작성한 가게입니다" / "별점은 1~5의 정수만 입력할 수 있습니다" / "존재하지 않는 가게입니다" / "입력값을 확인해 주세요" / "DB 오류가 발생했습니다"

### F-08 맛집 상세 조회
- **입력**: 가게 번호
- **처리**: 번호 검증(숫자 여부) → 가게 정보 조회 + 평균 별점·리뷰 수 집계 + 리뷰 목록 조회(최신순, 최대 10개)
- **출력**: 가게 정보, "평균 ★4.2 (리뷰 12개)", 리뷰 목록(닉네임, 별점, 내용, 작성일) / 리뷰가 없으면 "평점 없음", "작성된 리뷰가 없습니다" / "존재하지 않는 가게입니다"

### F-09 내 리뷰 수정 / 삭제
- **입력**: 내 리뷰 목록에서 리뷰 번호 선택, 수정 또는 삭제 선택, 수정할 별점·내용 / 삭제 확인(Y/N)
- **처리**: 내가 쓴 리뷰 목록 조회(0개면 종료) → 입력한 번호가 그 목록에 있는지 확인 → 수정은 별점·내용 검증 후 저장, 삭제는 확인 후 삭제 (Y/y만 진행)
- **출력**: "수정 완료" / "삭제 완료" / "취소되었습니다" / "작성한 리뷰가 없습니다" / "본인 리뷰만 선택할 수 있습니다"

## 4-1. 기능 명세 (선택 기능)

### O-01 맛집 검색
- **입력**: 검색 기준(이름 / 카테고리) 선택, 검색어
- **처리**: 빈 검색어 거부 → LIKE 조건으로 조회(PreparedStatement 사용, 앞뒤 공백 제거)
- **출력**: 검색 결과 목록(번호, 이름, 카테고리, 지역) / "검색 결과가 없습니다" / "검색어를 입력해 주세요"

### O-02 목록 페이징
- **입력**: 페이지 이동(다음 / 이전 / 번호)
- **처리**: 한 페이지에 5~10개씩 LIMIT/OFFSET으로 조회. 페이지 번호가 숫자가 아니거나 범위 밖이면 거부한다.
- **출력**: 해당 페이지의 맛집 목록과 현재 페이지 번호 / "이동할 수 없는 페이지입니다" / "등록된 맛집이 없습니다"

### O-03 목록에 평균 별점 표시
- **입력**: 없음 (F-05 목록 조회에 포함)
- **처리**: `RestaurantDAO`의 목록 SQL에 `LEFT JOIN review`와 `GROUP BY`를 추가해 가게별 평균 별점을 함께 집계한다. `ReviewDAO`는 호출하지 않는다.
- **출력**: 가게 번호, 이름, 카테고리, 지역, 평균 별점 (리뷰가 없으면 "평점 없음")

### O-04 비밀번호 변경
- **입력**: 현재 비밀번호, 새 비밀번호
- **처리**: 현재 비밀번호 일치 확인 → 새 비밀번호 빈 값 검증, 기존 비밀번호와 동일한지 확인 → 저장
- **출력**: "비밀번호가 변경되었습니다" / "현재 비밀번호가 올바르지 않습니다" / "기존과 다른 비밀번호를 입력해 주세요" / "입력값을 확인해 주세요"

### O-05 비밀번호 해시 저장
- **입력**: 없음 (F-01 가입, F-02 로그인, F-03 탈퇴 비밀번호 확인, O-04 비밀번호 변경에 적용)
- **처리**: 저장 전에 비밀번호를 해시(SHA-256 등)로 변환해 저장하고, 로그인 시 입력값을 같은 방식으로 변환해 비교한다. 해시 변환은 공통 유틸 클래스 한 곳에서만 한다. SHA-256 해시는 64자이므로 `member.password` 컬럼은 처음부터 VARCHAR(255)로 둔다.
- **출력**: 화면 변화 없음 (DB에는 해시값이 저장됨)

### O-06 본인 가게 리뷰 금지
- **입력**: 없음 (F-07 리뷰 작성에 포함)
- **처리**: `ReviewDAO`의 SQL 안에서 해당 가게의 등록자를 서브쿼리나 JOIN으로 확인해, 현재 로그인 회원과 같으면 거부한다. `RestaurantDAO`는 호출하지 않는다.
- **출력**: "본인이 등록한 가게에는 리뷰를 쓸 수 없습니다"

### O-07 맛집 중복 등록 방지
- **입력**: 없음 (F-04 맛집 등록에 포함)
- **처리**: 저장 전에 같은 이름과 주소의 가게가 이미 있는지 조회하고, 있으면 거부한다.
- **출력**: "이미 등록된 맛집입니다"

### O-08 카테고리 고정 목록
- **입력**: 카테고리 번호 (1. 한식 2. 중식 3. 일식 4. 양식 5. 기타)
- **처리**: 번호 범위(1~5)를 검증하고, 번호에 해당하는 카테고리 이름을 저장한다. F-04 등록, F-06 수정, O-01 검색에서 같은 목록을 쓴다.
- **출력**: 카테고리 목록 출력 후 선택 / "1~5 사이의 번호를 입력해 주세요"

## 5. 공통 예외 처리

- 메뉴와 번호 입력에 숫자가 아닌 값이 들어와도 프로그램이 종료되지 않도록 입력 View에서 재입력을 받는다.
- 숫자 입력 뒤 개행 문자 문제를 막기 위해 입력은 `nextLine()`으로 받아 변환한다.
- DB 연결 실패나 `db.properties` 누락 시 안내 메시지를 출력한다.
- `SQLException`은 한 가지 메시지로 뭉뚱그리지 않고, 필요한 오류 코드(1062 UNIQUE 위반, 1451 삭제 시 참조 중, 1452 참조할 행 없음)만 골라 처리한다. 나머지는 "DB 오류가 발생했습니다"로 처리한다.

## 6. 콘솔 메뉴 구조

```
[로그인 전]
 1. 회원 가입            (F-01)
 2. 로그인               (F-02)
```

## 7. 저장할 데이터

- **회원(member)**: 회원 번호, 아이디(UNIQUE), 비밀번호(VARCHAR(255), 선택 기능 O-05의 해시 저장을 위해 넉넉하게 잡는다), 닉네임(UNIQUE), 가입일
- **맛집(restaurant)**: 가게 번호, 등록자(회원), 이름, 주소, 지역, 카테고리, 등록일
- **리뷰(review)**: 리뷰 번호, 가게 번호, 작성자(회원), 별점(1~5), 내용, 작성일. (작성자, 가게) 쌍은 UNIQUE

**관계**: 회원 1:N 맛집, 회원 1:N 리뷰, 맛집 1:N 리뷰

**FK 삭제 규칙**
- 맛집 삭제 시 리뷰 함께 삭제: `review.restaurant_id` → `ON DELETE CASCADE`
- 회원 삭제 규칙은 따로 두지 않는다. `review.member_id`, `restaurant.member_id`는 기본 설정(삭제 거부)이어서, 리뷰나 가게가 있는 회원은 삭제되지 않는다. `restaurant.member_id`는 NOT NULL이다.

## 8. 역할 분담

난이도 점수(1~3)를 기준으로 기능 점수와 공통 작업 점수를 합쳐 팀원별 합계를 8점으로 맞췄다. 테이블 1개당 담당자 1명이라 같은 파일을 두 명이 수정하지 않는다.

| 팀원 | 담당 테이블 | 담당 기능 (3개) | 기능 점수 | 공통 작업 | 공통 점수 | 합계 |
|---|---|---|---|---|---|---|
| A (팀장) | member | F-01(1), F-02(2), F-03(2) | 5 | DBUtil·db.properties.example, LoginSession, Main·MainController 뼈대 | 3 | 8 |
| B | restaurant | F-04(1), F-05(1), F-06(2) | 4 | 모든 DTO 클래스, sample-data.sql | 4 | 8 |
| C | review | F-07(2), F-08(3), F-09(2) | 7 | schema.sql | 1 | 8 |

**공통 작업 (개발 시작 전 develop에 병합)**
- `sql/schema.sql`, `sql/sample-data.sql`
- `DBUtil`, `db.properties.example`, `LoginSession`
- 모든 DTO 클래스, `Main`, `MainController` 뼈대

**충돌 방지**
- 각자 자기 테이블의 DAO만 사용한다. B는 `ReviewDAO`를, C는 `RestaurantDAO`를 호출하지 않는다. 다른 테이블의 데이터가 필요하면(F-08, O-03, O-06) 자기 DAO 안의 SQL에서 JOIN이나 서브쿼리로 처리한다. F-08은 `ReviewDAO`에서 restaurant·review·member를 JOIN해 조회한다.
- 회원 탈퇴(A)는 `MemberDAO`에서 회원 삭제만 시도하고, 리뷰·가게가 있어 실패하면 FK 예외(오류 코드 1451)를 잡아 안내 메시지를 출력한다. 다른 DAO를 호출하지 않는다.
- PR은 기능 하나가 끝날 때마다 올린다.
